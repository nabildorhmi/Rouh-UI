# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> This is the concrete "show me" artifact for the visual gap the user named at project init ("lacks polish/premium feel," "not sure yet — show me"). Agency (Phase 2) and Podcast (Phase 3) must consume every token/rule below identically — that identical consumption is what makes "equal weight" and "elevated but on-brand" structural rather than a per-page judgment call. Nothing here changes the locked brand: Gotham font, orange `#c1622e` / gold `#d9a253`, and the 4 existing `GraphicAccent` elements are extended, not replaced.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — bespoke hand-rolled system, no component library/CLI |
| Preset | not applicable |
| Component library | none for styled UI; headless Radix primitives (`@radix-ui/react-accordion`, `@radix-ui/react-tabs`) may be added *only if* the process/FAQ layout needs them — installed unstyled, skinned entirely with this contract's tokens |
| Icon library | `lucide-react` (net-new, per `.planning/research/STACK.md`) — chrome only (chevrons, checkmarks, arrows); never substitutes for the 4 `GraphicAccent` brand strokes |
| Font | Gotham (weights 400/700/900), fallback `"Poppins", ui-sans-serif, system-ui, sans-serif` — already declared in `src/styles/index.css`, unchanged |

**Why no shadcn:** `components.json` does not exist and this project intentionally does not initialize it. Three independent signals agree: (1) `.planning/research/STACK.md` explicitly lists "any full component/UI kit (MUI, Chakra, Ant Design, Bootstrap)" under "What NOT to Use," reasoning that a themed kit fights the locked brand system and existing Tailwind-utility approach; (2) the codebase already has a working, minimal bespoke primitive layer (`Button`, `Modal`, `SectionHeading`, `GraphicAccent`) that this phase extends rather than replaces; (3) CONTEXT.md's discretion note assigns exact token values to this phase without instructing a tooling change. New shared primitives (`TestimonialsSection`, `ProcessSection`, cards) follow the existing pattern: local Tailwind utility classes with style-constant variables, no `@apply`, no CSS Modules, no component-class abstraction.

## Shape & Elevation (extends template — required by D-01/D-02)

| Radius token | Value | Usage |
|--------------|-------|-------|
| `rounded-lg` | 8px | Form inputs, small inline pills (existing) |
| `rounded-xl` | 12px | Small media thumbnails inside a card (e.g. episode art) |
| `rounded-2xl` | 16px | **Primary card radius** — all new cards (`TestimonialCard`, `ProcessStepItem` if card-shaped), modals, portfolio tiles. Matches existing `PlanCard`/`GuestTierCard`/`Modal`. Do not introduce a sharper or softer radius for new components (D-02: keep the shape language, elevate around it). |
| `rounded-full` | pill | Buttons, badges (`"Most popular"` tag), bullet dots — unchanged |

| Shadow token | Usage |
|--------------|-------|
| none (border only, `border border-black/10`) | **Default/rest state for all new cards** — minimal & precise (D-01) means elevation reads through spacing and border-contrast, not drop shadows, at rest |
| `shadow-lg` | Hover-lift on interactive cards only (new: `TestimonialCard` if ever made clickable, existing pattern extension) — pairs with the motion contract below, not a static treatment |
| `shadow-xl` | Featured/highlighted state only (existing: `PlanCard`/`GuestTierCard` `highlighted` variant — black background + border-orange). New primitives inherit this rule if they ever need a "featured" state; testimonials/process do not use it by default |
| `shadow-2xl` | Modal/overlay only (existing `Modal.tsx`) — reserved for content that floats above the page, never for in-flow cards |

**Graphic element placement (D-10):** the 4 `GraphicAccent` variants are sparing signature accents, 1-2 deliberate placements per page (hero, section divider) — never a recurring background motif or a per-card decoration on every card in a grid. Existing usage (`PlanCard`/`GuestTierCard`: one low-opacity `GraphicAccent` in a card's top-right corner) is the *outer bound* of density, not a pattern to replicate on every new card type. `TestimonialsSection`/`ProcessSection` should use at most one `GraphicAccent` per section (e.g. behind the section heading), not one per item.

## Spacing Scale

Base grid is 4px (Tailwind's native unit); values below are what's already established across the codebase and what new components must reuse — no new spacing values may be introduced.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, bullet-to-text inline spacing |
| sm | 8px | Compact element spacing (badge padding, tight gaps) |
| md | 16px | Default element spacing, page gutter (`px-4`) |
| lg | 24px | Card padding (`p-6`), gap between grid items, wide gutter (`px-6`) |
| xl | 32px | Card padding for feature/pricing cards (`p-8`), large content gaps |
| 2xl | 48px | — |
| 3xl | 64px | Section vertical padding, minimum (`py-16`) |

Exceptions (pre-existing, allowed — not new drift):
- `gap-3` (12px), `gap-5` (20px), `gap-10` (40px) — intermediate gaps already used in `PlanCard`, `Footer`, `AgencyTeaser`
- `py-14` (56px), `py-20` (80px), `py-24` (96px), `py-28` (112px) — section vertical padding varies by section weight (footer lighter, hero sections heavier); new `TestimonialsSection`/`ProcessSection` should use `py-20 sm:py-28` to match `AboutSection`'s heaviest existing section treatment, since trust/process content is a primary section, not a minor teaser
- Container width: `max-w-6xl` with `px-4 sm:px-6` gutters — reuse exactly, do not introduce a new container width

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Eyebrow/label | 12px (`text-xs`) | 700 bold, uppercase, `tracking-[0.2em]`, `text-orange` | 1.4 (default) |
| Body | 16px (`text-base`) | 400 regular | 1.5 |
| Card/step title | 24px (`text-2xl`) | 900 black | 1.2 |
| Section heading (display) | 30px / 36px responsive (`text-3xl sm:text-4xl`) | 900 black | 1.2 |

**Note on weight count:** the template calls for exactly 2 weights; this project's locked base styles (`src/styles/index.css`: `h1,h2,h3,h4 { font-weight: 900 }`) already establish 3 in production (400 body, 700 bold labels/CTAs, 900 black headings). This is a pre-existing brand constraint, not new scope creep — new components must reuse these exact 3, not introduce a 4th (e.g. no `font-semibold`/600 anywhere).

Secondary text uses opacity on black, not a separate gray palette: `text-black/60` (body-secondary, e.g. card descriptions), `text-black/40` (tertiary/meta), `text-black/80`–`/90` (on-dark-surface body text). New components reuse this scale — do not introduce `text-gray-*` utilities.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` white / `#000000` black | Page backgrounds and full-bleed sections (e.g. dark hero splits). No new background colors — D-03 locks backgrounds to white/black only |
| Secondary (30%) | `black/10`–`black/15` borders, `white`/`black` card surfaces | Card surfaces, section dividers, form input borders — structure and separation, not color |
| Accent (10%) | `#c1622e` orange / `#d9a253` gold, via `.bg-gradient-brand` / `.text-gradient-brand` | Reserved for: primary CTA buttons (`Button variant="primary"`), eyebrow labels, focus rings (`:focus-visible` outline), bullet-point dots in feature lists, the `text-gradient-brand` price/number treatment, "Most popular"/featured badges, hover-state link color and icon accents (e.g. arrow links). **Never** as a section/page background — D-03 is explicit that orange/gold stay accent-only, no full-section color blocks |
| Destructive | not applicable this phase | No delete/cancel/destructive actions exist in `TestimonialsSection`/`ProcessSection` or any Phase 1 primitive. If a future phase needs one (e.g. a reservation-cancel flow), it must not reuse orange/gold (accent is reserved per above) — flag for that phase's own UI-SPEC to define a dedicated red/warning token, do not improvise one here |

Accent reserved for (explicit list, per above): primary CTA buttons, eyebrow labels, focus-visible outlines, feature-list bullet dots, gradient price/number display, featured/highlighted badges, hover-state accents on text links and chevrons. Every other surface stays white/black/gray-via-opacity.

## Motion & Micro-interactions (extends template — required by D-05/D-06 and Success Criterion 4)

| Pattern | Spec |
|---------|------|
| Scroll reveal | `motion`'s `whileInView`: opacity `0 → 1`, `translateY` `16px → 0`, duration ~400ms, `ease: "easeOut"`, `viewport={{ once: true, margin: "-80px" }}`. Applied to section containers and, with `staggerChildren: 0.08`, to grid children (`TestimonialCard`s, `ProcessStepItem`s) |
| Hover — buttons | Existing pattern, reuse verbatim: `hover:scale-[1.03] active:scale-[0.98]` (already in `Button.tsx`) — do not invent a second button-hover treatment |
| Hover — bordered cards | Existing pattern, reuse verbatim: `border-black/10 hover:border-orange/40 transition-colors` (already in `ServicesGrid`) for any new card that should read as interactive |
| Hover — non-interactive cards (e.g. `TestimonialCard`, which has no click target) | No hover state — do not add a hover affordance to a card that doesn't do anything on click; that's a false interactivity signal |
| Reduced motion | `useReducedMotion()` from `motion` disables scroll-reveal and hover-scale entirely (render final state immediately, no transition) — per D-06, this is an on/off switch, not a "smaller motion" fallback |
| First proof-of-wiring interaction (Success Criterion 4) | Scroll-reveal on `TestimonialsSection`'s card grid is the designated first micro-interaction — it's the most visible, lowest-risk place to confirm `motion` + `tw-animate-css` are correctly installed and wired before any page depends on them |

Do not add: parallax, staggered multi-property reveals beyond the single stagger above, page-transition animation, or scroll-scrubbed/pinned effects (all explicitly out of scope per D-05 and `.planning/research/STACK.md`'s "what NOT to use" guidance on GSAP-class effects).

## Copywriting Contract

This is an infrastructure phase — no page ships final copy here. The contract below covers the copy this phase *does* produce (sample/placeholder data for the shared components) and the standard elements for future phases to inherit.

| Element | Copy |
|---------|------|
| Primary CTA | Not applicable this phase — no new page-level CTA is introduced; `Button`/`LinkButton` are reused as-is. Phases 2-3 define their own CTA copy in their own UI-SPEC |
| Empty state | `TestimonialsSection`/`ProcessSection` must never render a visible "no content" message — if given an empty array, the section renders nothing (returns `null`) rather than showing empty-state copy. A trust-building section admitting "nothing to show" undermines the section's purpose, and per D-09 the data itself is contractually never empty (2+ per category minimum) |
| Error state | Not applicable — all data is static, build-time imported (`src/data/*.ts`); there is no fetch, so no runtime error path exists to write copy for |
| Destructive confirmation | Not applicable — no destructive actions in this phase's components |
