# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This phase is content + composition, not visual invention.** Every component this page needs (`TestimonialsSection`, `ProcessSection`, `PortfolioShowcase`, `PlanCard`, `ServicesGrid`, `ReservationModal`) already exists, built to the Phase 1 design contract (`.planning/phases/01-design-system-contract-shared-primitives/01-UI-SPEC.md`). ### Composition-specific: page section order and inter-section spacing (this phase's actual spacing contract)

Locked order (CONTEXT.md D-01): **Hero → Plans → Services → Portfolio ("Selected work") → Testimonials → Process**. `ReservationModal` stays last in the JSX tree regardless (it's a fixed/absolute overlay — position in the DOM tree does not affect visual placement).

| # | Section | Container / padding | Rationale |
|---|---------|----------------------|-----------|
| 1 | Hero | `pt-16 sm:pt-24 pb-16` (unchanged) | First section — only section needing top-of-page padding |
| 2 | Plans | `py-16 sm:py-20` (reduced from the pre-reorder standalone `py-20`) | Now sits directly under the hero; `py-16 sm:py-20` keeps the Hero→Plans gap in the 128–176px range rather than stacking two full `py-20` paddings (which would push the primary CTA further down than D-01's "reduce friction to booking" intent) |
| 3 | Services | `pb-20` only, no top padding (unchanged) | Flows directly under Plans' bottom padding — ~80px total gap, matches the pre-reorder Hero→Services gap this page already used |
| 4 | Portfolio ("Selected work") | `bg-black/[0.02] border-y border-black/5` wrapper, inner `py-20` (unchanged) | Full-bleed gray section — ~160px total gap before/after is an intentional heavier visual break, now doing double duty as the transition after three consecutive white sections (Hero/Plans/Services) |
| 5 | Testimonials | Component-owned `py-20 sm:py-28` (do not wrap in an extra `<section>`) | `TestimonialsSection` renders its own section wrapper — an outer wrapping section would double the padding |
| 6 | Process | Component-owned `py-20 sm:py-28` (do not wrap in an extra `<section>`) | Same as above — `ProcessSection` is self-contained |
| — | ReservationModal | N/A (overlay) | Rendered last in JSX, unconditionally, regardless of Plans' position — `open={!!selectedPlan}` |

**Do not** introduce a new padding value (e.g. `py-24` between two of these) to "balance" the rhythm further — the table above is the complete, final spacing contract for this page.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|

## Mobile Layout Behavior (composition-specific — required by Success Criterion 4, DSGN-02)

| Section | Desktop grid | Mobile (< `sm`, 640px) behavior |
|---------|--------------|----------------------------------|
| Plans | `sm:grid-cols-3` | Single column, full-width `PlanCard`s stacked vertically with `gap-8`; `highlighted` (Growth) card keeps its `shadow-xl`/black-bg treatment at all widths |
| Services | `sm:grid-cols-2 lg:grid-cols-3` | Single column below 640px, 2-up at `sm`, 3-up at `lg` — unchanged existing `ServicesGrid` behavior |
| Portfolio | `sm:grid-cols-3` | Single column below 640px — `aspect-[4/3]` gradient box keeps its aspect ratio at every width, no cropping/distortion |
| Testimonials | `grid-cols-1 sm:grid-cols-2 lg:grid-cols-3` | Single column below 640px (existing `TestimonialsSection` behavior, unchanged) |
| Process | `grid-cols-1 sm:grid-cols-2 lg:grid-cols-4` | Single column below 640px, 2-up at `sm`, 4-up at `lg` (existing `ProcessSection` behavior, unchanged) |
| ReservationModal | N/A | Existing responsive modal behavior (Phase 1-verified at 375px viewport per `01-03-SUMMARY.md`), unchanged — `PlanCard`'s "Select this plan" button remains a full-width tap target (`className="w-full"`) at every viewport width |

No new breakpoints, no new responsive utilities — every grid above is an existing, already-verified pattern from Phase 1/pre-existing code. This phase's only mobile-relevant risk is the reordered Plans section: confirm on a 375px viewport that Plans, now positioned right after the hero, doesn't crowd the hero's bottom padding (per the spacing table above) and that the `highlighted` Growth card's dark background doesn't visually collide with the hero if the hero itself uses a dark split (it does not — hero is a plain light section per current `Agency.tsx`).
